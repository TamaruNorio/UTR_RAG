**GQ-017**  
正常な0枚としては扱えません。code1=68hは、アンテナ断線検知時のエラー（CMD_ANT_ERROR）です。アンテナ接続を確認する必要があります。正常に読み取り0枚で終了した場合は、枚数0の読み取り完了ACKが返ります。  
出典：§7.6 紙面p.317、§7.5 Inventory応答 紙面pp.263–264。

**GQ-024**  
いいえ。サイクル終了通知の設定は「自動読み取りモード」の場合に有効です。単発Inventory／InventoryReadでは、タグデータ応答の後に完了ACKが返り、読み取り0枚でも完了ACKが1回返ります。通知OFFを理由に、完了ACKを待たず成功とは判断できません。  
出典：§7.4「自動読み取りモード時の読み取りサイクル終了時のレスポンス」紙面p.234、§7.5 紙面pp.263–264、268–269。

**GQ-025**  
取り除けません。TID付加OFFでも、tid_lengthに相当するn3の1バイトは残り、値は00hです。省かれるのはTID本体だけです。データ長は引き続き「7+n1+n2+n3」で、OFF時の実例でもETX直前にn3=00hがあります。  
出典：§3.9 紙面p.59、§7.5 InventoryRead応答 紙面p.268。

**GQ-048**  
DATA中の03hや0Dhでは区切れません。バイナリ形式なので、データ長から全長「データ長+7」を求め、所定位置のETX・SUM・CRを確認します。途中受信だけでは直ちに不正と断定せず、必要なバイトが揃うまで判断を保留します。受信待ちの期限は添付資料では不明です。  
出典：§5.2 紙面p.99、§5.3 紙面p.100。

**GQ-049**  
エラーではありません。加算結果の下位1バイトを採用するため、13FhならSUMは3Fhです。STXからETXまでを両端含めて加算し、その範囲内の予約バイトも含めます。SUM自身とCRは含めません。  
出典：§5.2 紙面p.99、§5.3 紙面p.100。

**GQ-056**  
使えません。UTR-SUN02-4CHのROM Ver.2.052以前は下限10msで、1msになるのはVer.2.100以降です。「1～4000」という一般的な範囲だけでは、この機種・ROM条件を覆せません。なお、この設定は自動読み取り時の連続出力最大時間で、コマンドモードでは実行終了時にキャリアOFFとなります。  
出典：§7.4「キャリア送信時間」紙面p.218。

**GQ-099**  
いいえ。DATAを0始まりで数える場合、DATA[0]は15h、DATA[1]は読み取りデータの**バイト数**です。1 Wordは2バイトなので、成功応答のDATA[1]は02hです。外側のデータ長は、詳細コマンドと長さ欄も含めて04hになります。  
出典：§7.5.3 紙面pp.272–273。

**GQ-111**  
分かりません。設定ACKが示すのはリーダライタへのAccessパスワード設定成功で、タグ認証成功ではありません。非ゼロ設定後にRead等の対象コマンドを実行するとAccess認証が行われます。設定値はRAM上に保持され、読戻しはできず、ACKにもパスワードは含まれません。  
出典：§7.4.23 紙面pp.226–227、§7.5.3 紙面pp.271–272。

**GQ-253**  
USM06はUTR-SUN02V-8CH、USM08はUTR-SUN02-8CHで、いずれもUTR-S201シリーズです。UMP01はUTR-S101シリーズ（主な機種：UTR-SU01-3CH／UTR-SN01-3CH）で、参照先は別の「UTR通信プロトコル説明書」です。未知シリーズの対応は資料にないため、既知機種へ推定で割り当てられません。  
出典：「ROMバージョン情報」シリーズ対応表 紙面p.2。
