# PDF由来テキストとRAG文書の小規模比較

実施日: 2026-09-16。保守者の「小規模にやってみてください」という追加依頼に基づく、今回限りの予備比較です。

## 結果

今回の9問では、両条件とも結論の誤りはありませんでした。厳密な説明項目の充足ではRAG側が1回答分上回りましたが、入力・出力トークン合計はRAG側が1.23%多く、費用削減は確認できません。原典PDF全体とRAG全体の比較結果ではありません。

|---|---:|---:|

| 実際の金額 | 取得不可 | 取得不可 |

必須説明の全項目充足率の差は+3.7ポイントです。Aの1回目のGQ-111は「設定ACKはタグ認証成功を示さない」「読戻し不可」と正しく答えましたが、「ACKにパスワードは含まれない」という明示がありませんでした。これを説明不足と判定しました。1回答の省略による差であり、一般的な正答率改善の実証とは扱いません。

引用は内容採点と分けて確認しました。BのGQ-017はカードの根拠を示しましたが、68hの原典ページp.317を示していません。今回Bへ渡した抜粋にそのページ情報を含めなかったためで、RAG全文の欠落とは判断しません。Aはp.317を引用しました。Aは節番号が7.5等の大きい区分になる回答がありましたが、紙面ページで該当箇所を追えます。

## 実施条件

- モデルはgpt-6-astra、reasoning_effort=high、Codex CLI 0.154.0-alpha.6.2。ChatGPTログインを使用。各回は履歴を引き継がない一時セッション。
- 対象はGQ-017・024・025・048・049・056・099・111・253。1回に9問をまとめ、条件ごとに3回、計6セッション・54回答。54個の独立した質問セッションではありません。
- 同じ質問、回答字数目安、資料だけを根拠にする指示、ツール禁止を共通化。回答イベントを確認し、有効6回のツール呼出しはすべて0。
- Aは公式PDF Ver.1.17の17ページの抽出テキスト、Bは10文書の17節。問いに対応する関連箇所を作業者が選んで入力文へ直接添付しました。各PDFページ・各Markdown節は[資料一覧](evaluation/20260916/manifest.json)に記録。
- 採点基準は[25項目](evaluation/20260916/rubric.json)。最初の回答を読む前に固定し、直接の質問範囲を超える補足は必須点から除外。文書整備と同じAIによる目視採点で、人間の独立採点・条件を隠した採点ではありません。
- 元のPDF全体をファイル検索させる試行A1は、読み取りコマンドが実行ポリシーで拒否されたため中止し、採点対象外。安全設定を緩めず、直接添付方式へ変更しました。この失敗試行や準備・採点に使った親会話の使用量は表に含めていません。

## 利用量と費用の区別

トークン数はCLIのturn.completedのusage実測値です。入力には資料以外の実行環境の文脈も含みます。キャッシュ入力は入力の内数、推論出力は出力の内数として、二重加算しません。試行ごとにキャッシュ量が異なるため、合計トークンだけから金額を計算できません。月額利用枠の消費割合やAPI請求額への換算もしません。

今回の資料文字数は入力文を含めAが21,084文字、Bが22,991文字でした。RAGの関連説明には重複もあり、「Markdownにしただけで必ず入力が減る」とは言えません。文字数は費用の代用には使っていません。

## 限界と判断

既存の文書整備に使った公開質問なので、Bに有利な選題の可能性があります。9問は全54カードの代表標本ではなく、同じ入力の3回反復で標本が27種類に増えたわけでもありません。差が小さく、統計的な優位性は主張しません。

AはPDFの画像・全体をモデルへ渡した試験ではなく、抽出テキストの関連ページです。図・結合セルの読解や資料探索の利点は測っていません。Bもベクトル検索や索引から自力で探した結果ではありません。関連資料の選び方、形式、説明の追加という複数の差があり、Markdown形式だけの効果に分解できません。

この範囲で言えるのは「両方とも主要な問いには正しく答えた。RAGは説明を補いやすい一方、今回はトークン削減にはならなかった」です。大規模試験は追加せず、保留仕様も変更しません。
