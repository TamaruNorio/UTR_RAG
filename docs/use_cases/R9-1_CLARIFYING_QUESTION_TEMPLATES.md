# R9-1 Clarifying Question Templates

## 1. 最小確認版

- 対象機器は何ですか。
- 接続方式はUSB、LAN、Serialのどれですか。
- 接続情報はCOMポート/ボーレート、またはIP/ポートのどれですか。
- 読みたいデータはEPC、TID、USER、その他のどれですか。
- まず、既存設定のまま読む前提でよいですか。それとも、読み取り安定化のために周波数、送信出力、Inventory条件の調整まで検討しますか。

## 2. 読み取り安定化版

- どの条件で不安定になりますか。
- 読み取り距離、タグ枚数、周囲タグ、アンテナ構成を教えてください。
- 安定性優先ですか、速度優先ですか。
- 設定変更が必要な場合、一時的な変更でよいですか。それとも電源再投入後も残るようにFLASH保存が必要ですか。
- Level 4以上の操作を検討する場合、明示確認者は誰ですか。

## 3. 複数タグ版

- 想定タグ枚数は何枚ですか。
- タグ同士の距離や配置は決まっていますか。
- 重複読み取りを許容しますか。
- CSV保存やタグIDマスクは必要ですか。
- Inventory Param変更まで検討してよいですか。

## 4. 業務アプリ向け C# 版

- SDKを利用できる環境ですか。
- Windowsアプリ、サービス、Web連携のどれですか。
- 実機制御はアプリ内で行いますか、別プロセスで行いますか。
- ログ、CSV、エラー通知、再接続の要件はありますか。
- 本番導入判断と実機確認は利用者側で行う前提でよいですか。

## 5. 検証スクリプト向け Python 版

- 既存サンプルを使う前提でよいですか。
- 実機確認環境ですか、机上検討ですか。
- 読み取り回数、タイムアウト、CSV保存先を教えてください。
- タグ固有IDをログに残さずマスクする方針でよいですか。

## 6. Webhook / Node.js 版

- Node.jsは実機接続PCで動きますか、サーバ側で動きますか。
- Webhook送信先、認証、再送方針は決まっていますか。
- タグ固有IDを送信する場合、マスクまたは匿名化が必要ですか。
- 実機制御部分は既存SDKまたは既存プロセスに分離しますか。

## 7. 設定変更を伴う場合

- 変更したい設定は周波数、送信出力、Inventory Param、アンテナ、その他のどれですか。
- 必要性と期待効果は何ですか。
- 日本国内仕様の範囲であることを確認済みですか。
- 元に戻す方法はありますか。
- 明示承認者と実施ログの保存先を教えてください。

## 8. FLASH保存を検討する場合

- FLASH保存が必要な理由は何ですか。
- 一時変更では不足する理由は何ですか。
- 変更前設定のバックアップ方法は決まっていますか。
- 復旧手順と復旧確認方法はありますか。
- 明示承認がない場合はHOLDにします。

## 9. HOLDにする場合

- 対象機器、地域条件、接続情報、読み取り対象、設定変更許可のいずれかが不足しています。
- 日本国内仕様の範囲か判断できません。
- Level 4以上の操作に必要な明示確認がありません。
- FLASH保存に必要な明示承認と復旧手順がありません。

## 10. 日本国外利用が示された場合

海外利用、海外設置、海外販売を想定していますか。想定している場合、本RAGの対象外となるため、国内仕様のまま実装提案はできません。
