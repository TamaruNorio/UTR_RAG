# R9-1 Requirement Clarification Guide

## 1. 目的

自然言語の依頼に対して、生成AIがすぐにコードを書かず、RFID制御に必要な確認質問を行い、日本国内仕様の範囲で安全に読み取り条件を整理できるようにする。

## 2. 対象範囲

- UTR-S201シリーズ向けの読み取り要件整理
- 日本語利用者向けの確認質問
- USB、LAN、Serial接続を想定した机上検討
- 実装方針、ログ方針、実機確認方針の整理

## 3. 日本国内向け前提

本ガイドは日本国内向け、日本の電波法準拠機器、国内仕様の設定範囲を前提とする。海外利用、海外設置、海外販売、海外周波数、海外認証が関係する場合は対象外として `HOLD` とする。

## 4. すぐ実装してはいけない依頼例

- 「とにかく一番遠くまで読めるようにして」
- 「送信出力を最大にして」
- 「周波数を固定して」
- 「Inventory条件を変更して保存して」
- 「FLASHに書いて恒久化して」
- 「海外拠点でも同じ設定で使いたい」
- 「仕様は分からないがC#コードだけ作って」

## 5. 最低限確認すべき項目

- 対象機器
- 接続方式 USB / LAN / Serial
- 接続情報 COMポート、ボーレート、IP、ポート
- 読みたいデータ EPC / TID / USER / その他
- 読み取り回数 1回 / 一定時間 / 連続
- タグ枚数 1枚想定 / 複数想定
- ログ保存の要否
- CSV保存の要否
- 既存設定のまま実施するか
- 設定変更を許可するか
- 実機確認環境か、机上検討か

## 6. 追加最適化時に確認すべき項目

- 読み取り距離
- 読み取り速度
- 安定性優先か速度優先か
- 周囲タグの有無
- アンテナ構成
- 使用アンテナ番号
- 周波数固定の要否
- キャリアセンスの扱い
- 送信出力変更の要否
- Inventory Param変更の要否
- 一時変更か永続変更か
- FLASH保存の要否
- 復旧方法
- 承認者または確認者

## 7. HOLDにすべき条件

- 対象機器、接続方式、地域条件が不明
- 海外利用または海外販売が示されている
- 日本国内仕様から外れる可能性がある
- 周波数、送信出力、Inventory Param、FLASH保存の必要性が不明
- 復旧方法が不明
- Level 4以上の操作に明示確認がない
- Level 5操作に明示承認と復旧手順がない

## 8. 生成AIへの応答ルール

- 不足情報がある場合は、実装前に確認質問を行う。
- 既存設定で実施できる範囲を先に提案する。
- 設定変更が必要な場合は、必要性、実機影響、復旧方法、承認条件を説明する。
- Level 4以上の操作は、生成AIが勝手に実装しない。
- 不明点は推測で埋めず、`HOLD` または要確認にする。

## 9. 良い確認質問例

- 対象機器、接続方式、接続情報を教えてください。
- 読みたいデータはEPC、TID、USERのどれですか。
- まず既存設定のまま読む前提でよいですか。それとも、読み取り安定化のために周波数、送信出力、Inventory条件の調整まで検討しますか。
- 設定変更が必要な場合、一時的な変更でよいですか。それとも電源再投入後も残るようにFLASH保存が必要ですか。
- 実機確認環境ですか。机上検討ですか。

## 10. 悪い応答例

- 情報不足のまま実機送信用コードを書く。
- 周波数や送信出力を確認なしで変更する。
- FLASH保存を当然の前提にする。
- 海外利用を国内仕様のまま処理する。
- 「全コマンド確認済み」「安全確認完了」と断定する。
