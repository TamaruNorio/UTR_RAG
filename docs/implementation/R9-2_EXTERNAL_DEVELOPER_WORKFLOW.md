- `README.md`
- R9-0 scope policies

- R9-2 implementation output requirements

## 2. 自然言語で依頼する前に整理すること

- 対象機器
- 接続方式
- 接続情報
- 読み取り対象
- 読み取り回数
- ログ/CSV要否
- 設定変更の可否
- 実機確認環境の有無

## 3. 生成AIに渡す情報

日本国内仕様前提、対象機器、接続方式、対象言語、読み取り目的、操作レベル、設定変更可否、HOLD条件を渡す。

## 4. AIが質問すべきこと

不足している機器情報、接続情報、読み取り対象、ログ方針、設定変更可否、Level 4以上の承認有無を質問する。

## 5. 実装方針の確認

コード生成前に、通信方式、処理分割、ログ、タイムアウト、エラー処理、実機確認方法を確認する。

## 6. コード生成

v006 External Review Candidate向けの候補文書では、実コードはこのリポジトリに追加しない。対象言語の実装リポジトリまたは利用者環境で作成する。

## 7. 机上確認

設定値、状態遷移、ログ項目、HOLD条件、異常系をレビューする。

## 8. 実機確認

既存設定、短時間、小範囲から始める。実機確認ログはタグ固有IDや顧客情報をマスクする。

## 9. 異常系確認

タグなし、応答なし、通信断、NACK、タイムアウト、ログ保存失敗を確認する。

## 10. 本番導入前確認

本番導入判断は利用者側で行う。社外レビュー候補文書だけで本番利用可能とは扱わない。

## 11. 当社サポート範囲

通信仕様、注意点、安全分類、混同防止ルール、基準実装、実機確認済み範囲、HOLD事項の提示。

## 12. 利用者側責任範囲

生成コードのレビュー、実装環境への適用、実機確認、異常系試験、本番導入判断、海外利用可否判断。
