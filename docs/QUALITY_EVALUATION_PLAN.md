# 代表質問による文書点検の手順

## 目的と範囲

2026-09-16の保守者指示により、作業を「仕様に忠実で、AIと人間が実装時に参照しやすい文書の整備」に絞ります。代表質問を使い、文書の抜け・矛盾・参照漏れを点検します。

AI回答の比較試験、正答率・利用量・費用の実測、試験環境や評価器の準備は現在の工程と完了条件から外します。将来、効果の実証が必要になった場合に別途扱います。「PDFより正確・安価」という実証済みの主張はしません。

## 1. 必要な説明を確認する

[既存質問](../qa/golden_queries.yaml)と[初回12問の点検項目](ANSWER_EVALUATION_PILOT.md)を使い、対象カード・共通説明・関連資料を確認します。PDFの版・節・ページを追え、条件と結論を取り違えずに読めるかを調べます。すでに十分な記載があれば追記しません。

原典の明記、フィールドからの計算、実装・運用上の判断を区別します。質問と直接関係しない補足事項を必須の本文追加にしません。正常0枚、NACK、設定依存、機種・ROM不明、資料不足、過去記録との混同を優先します。

## 2. 不足・矛盾だけを直す

根拠が明確な記載不足・参照漏れは修正し、原典の訂正や不明仕様は独自に確定しません。[原典照合一覧](current/SOURCE_REVIEW_STATUS.md)のOPEN-014～028とその他の未確認仕様は回答待ちのまま保留します。同じ質問を繰り返しません。

点検結果は、質問ID、確認文書と節、原典位置、結果、必要な修正、残る制限を短く記録します。結果は「記載あり・修正不要」「修正済み」「保留」とし、AIの正答率や実機PASSへ置き換えません。

## 3. 検証と区切り

編集後は既存のfrontmatter・リンク検査とチャンク生成で構造を確認します。確認した範囲を[改善計画](IMPROVEMENT_PLAN.md)と引き継ぎに残します。最初は12問の点検を区切りとし、残る文書課題を整理します。全290問の一律点検や新たな比較試験を自動的に追加しません。

仕様の重大な疑義が残る場合は、その制限を明示します。文書点検の完了と、全仕様の確定・実機動作保証は区別します。

## 追加依頼による小規模比較

保守者の追加依頼により、2026-09-16に[小規模比較](SMALL_COMPARISON_REPORT.md)を別枠で実施しました。関連抜粋を直接渡す9問×2条件×3回の予備比較であり、PDF全体の画像読解やRAGの検索性能は対象外です。既存の文書点検の完了条件は広げず、実費・一般的な優位性は未検証のままです。
