# R8-3 Real-Device Test Plan

## 目的

この文書は、R7-5A成果物をRC候補または社内pre-RCとして扱えるか判断するための実機確認計画です。

R8-3では、接続・切断・読み取り系・タイムアウト・ログ確認を、読み取り専用かつ非永続操作を原則として実施します。

## 実機確認の原則

- まず読み取り専用・非永続操作から確認する
- 設定変更は行わない
- FLASH書き込みは行わない
- 周波数変更は行わない
- 送信出力変更は行わない
- UHF_SetInventoryParamは自動送信しない
- 8CHアンテナ自動切替は行わない
- 異常時は即停止し、ログを保存する

## 確認対象

実機確認時は以下を記録します。実IPアドレス、顧客名、設置先名などの識別情報はマスクします。

| 項目 | 記録内容 |
|---|---|
| PC環境 | OS、ツール名、ツール版数 |
| 接続方式 | シリアル、TCPなど |
| 対象機器 | UTR-S201シリーズの型番 |
| ファームウェアまたはROM情報 | 確認可能な範囲で記録 |
| COMポートまたはIPアドレス | 実値はマスクして記録 |
| ボーレートまたはTCPポート | 使用値を記録 |
| アンテナ接続状態 | 接続数、接続先、固定状態 |
| 使用タグ | タグ種別、数量、配置 |
| 実施者 | 氏名または識別子 |
| 実施日時 | JSTで記録 |
| 実施場所 | 社内検証室など。顧客名はマスク |

## 確認シナリオ

### Scenario 1: 接続・切断確認

目的:
接続、タイムアウト、切断が安全に行えることを確認する。

確認内容:

- 接続開始
- 接続成功
- タイムアウト設定
- 切断
- 再接続可否

判定観点:

- 接続失敗時に無限待機しない
- 切断後にポートまたはソケットが解放される
- 再接続時に前回状態が残らない

### Scenario 2: ステータス取得または読み取り専用コマンド確認

目的:
機器状態を破壊的でない方法で確認する。

注意:
対象コマンドは、実機影響と仕様を確認した上で選定する。不明な場合は送信しない。

判定観点:

- 応答が取得できる
- 応答長と解析結果に矛盾がない
- エラー応答時に停止できる

### Scenario 3: Inventory系確認

目的:
タグ読み取りの基本挙動を確認する。

注意:
Inventoryは電波送信を伴う可能性があるため、実施環境、アンテナ、出力、地域設定を事前確認する。UHF_SetInventoryParamは送信しない。周波数や送信出力は変更しない。既存設定の範囲で実施する。

判定観点:

- 既存設定の範囲でタグ応答を確認できる
- タグなしの場合に安全に終了する
- 予期しない応答がある場合はHOLDにする

### Scenario 4: タイムアウト確認

目的:
タグなし、応答なし、通信断などで安全にタイムアウトすることを確認する。

判定観点:

- タイムアウト時間が記録される
- タイムアウト後に通信を終了できる
- 再接続または再試行の可否が記録される

### Scenario 5: ログ確認

目的:
実行時の接続、送信、受信、切断、エラーが記録できることを確認する。

判定観点:

- 接続開始と切断が記録される
- 送受信イベントが記録される
- エラーとタイムアウトが記録される
- ログに顧客名、実IPアドレスなどの非公開情報が残る場合はマスクする

## HOLD条件

以下の場合はHOLDとします。

- 実機が応答しない
- 接続が不安定
- タイムアウト処理が不明
- レスポンス解析に不明点がある
- 仕様と異なる応答がある
- 安全禁止事項に触れそうな操作が必要
- 周波数、出力、FLASH、アンテナ設定変更が必要
- 実施環境が不明
- ログが保存できない
