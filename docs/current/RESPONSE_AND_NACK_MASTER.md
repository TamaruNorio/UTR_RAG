# レスポンス・NACKマスタ

## 1. 目的

この文書は、UTR-S201シリーズの実装で必要になるレスポンス処理とNACK処理の考え方を整理します。

公式PDFが一次情報です。この文書は、AIに実装・レビューを依頼するときの補助資料です。

## 2. 区別するレスポンス

実装では、少なくとも以下を区別してください。

- ACK
- NACK
- timeout
- 無応答
- 複数レスポンス
- 完了レスポンス
- 自動読み取りやRFタグ応答に伴う非同期レスポンス

RFタグ通信系では、1回の送信に対して複数フレームを受信する場合があります。単純な「1送信1応答」と決め打ちしないでください。

## 3. ACK解釈の前提

ACKの意味、データ長、後続レスポンスの有無は、コマンド番号だけで固定解釈しません。実装では、起動時または実機送信前に次のスナップショットを取得し、その値に基づいてACKを解釈してください。

| 確認項目 | ACK解釈への影響 |
|---|---|
| ROMバージョン、シリーズ名、対象機種 | 対応コマンド、アンテナ系コマンド、レスポンス形式の前提を決める |
| 物理アンテナ容量、接続OKアンテナ | アンテナ番号を含む応答、アンテナ切替応答、アンテナエラーの解釈に使う |
| リーダライタ動作モード | コマンド応答と自動読み取り・非同期応答を切り分ける |
| アンテナID出力 | RFタグ応答内にアンテナ番号が含まれるかを決める |
| TID付加 | Inventory系応答のデータ長とTID領域の有無を決める |
| EPC/UII応答設定、EPCバッファリング | RFタグ応答の出力単位、蓄積応答、後続応答の有無を決める |
| 読取完了応答 | 読取サイクル終了時の完了ACKを待つべきかを決める |
| アンテナ切替完了応答 | 自動切替時の切替完了ACKを待つべきかを決める |
| キャリア検知応答 | 他キャリア検知イベントを受信対象に含めるかを決める |
| RAM設定かFLASH設定か | 一時変更、復元、再起動後保持の扱いを決める |

このスナップショットを取らずに「ACKの2バイト目は常に同じ意味」と決め打ちしないでください。設定によって、同じ位置のバイトがアンテナ番号、詳細状態、データ長の一部、または予約値として扱われる場合があります。

## 4. 設定依存レスポンスの代表例

| 条件 | 実装上の扱い |
|---|---|
| アンテナID出力ON | RFタグ応答にアンテナ番号が含まれる前提でパースする |
| アンテナID出力OFF | アンテナ番号がない前提でパースし、前回設定値だけで実受信ANTを断定しない |
| TID付加OFF | Inventory系応答でTID長0またはTID領域なしとして扱う |
| TID付加ON | Inventory系応答でTID領域を含む可変長応答として扱う |
| 読取完了応答ON | タグ応答とは別に読取完了ACKを受信する前提で待ち受ける |
| 読取完了応答OFF | 読取完了ACKを必須条件にしない |
| アンテナ切替完了応答ON | 自動アンテナ切替ごとの完了ACKを受信対象に含める |
| アンテナ切替完了応答OFF | 切替完了ACKが返らないことを異常扱いしない |
| キャリア検知応答ON | 他キャリア検知イベントを受信対象に含める |
| キャリア検知応答ONかつイベント0件 | 周囲に他キャリアがない場合は正常な未観測として扱う |
| キャリア検知応答OFF | キャリア検知イベントが返らないことを異常扱いしない |

UTR-SUN02-4CH / USM02 Ver.2.052 の実機確認では、ANT0〜2の自動切替、TID付加OFF/ONによる応答長変化、読取完了応答、アンテナ切替完了応答、EPC応答設定RAMの相互反映、RAM設定復元、コマンドモード復元を確認済みです。キャリア検知応答設定の読戻しは確認済みですが、キャリア検知イベントは環境依存のため、イベント0件を失敗として扱いません。

## 5. コマンドカード内のHex例の読み方

各コマンドカードには、実装時に迷いやすいACK、NACK、RFタグ応答、完了応答の例を記載します。

| 表記 | 意味 |
|---|---|
| `TX` | 上位機器からリーダライタへ送信するコマンド例 |
| `RX` | リーダライタから上位機器へ返るレスポンス例 |
| `02` | STX |
| `ADR` | レスポンスのアドレス位置。通常はリーダライタID。アンテナID出力ONのRFタグ応答では読み取りANT番号になる |
| `30` | ACK |
| `31` | NACK |
| `6C` | RFタグ読み取りデータなどの非同期・タグデータ系レスポンス |
| `LEN` | データ部バイト数 |
| `SUM` | STXからETXまでのSUM値 |
| `0D` | CR |
| `<...>` | 可変長データまたはPDF該当節で定義されるフィールド |

PDFに完成Hex例があるものは、カード内に完成Hex例として記載します。PDF例がない、または設定値によりACKデータ部が変わるものは、完成Hexとして誤読されないように構造例で示します。

実機ログ由来のraw EPC / UII / TID、顧客タグ固有値、製造番号、パスワードはGitHubに載せません。PDF掲載例または説明用の固定例として扱える値だけを記載してください。

## 6. NACK処理

NACKは、共通NACK形式と各コマンドの該当節を併せて確認します。

確認する代表例は以下です。

- SUMエラー
- フォーマットエラー
- timeout
- LBTエラー
- アンテナエラー
- UHF ICエラー
- RFタグ無応答
- Accessパスワード関連エラー
- メモリロック関連エラー

予約バイトは、PDFで意味が定義されていない限り独自解釈しません。

## 7. 実装時の注意

- timeout値を固定値だけで扱わず、接続方式とコマンド種別に応じて設定する。
- ACK、NACK、timeout、無応答を同じエラーとして扱わない。
- NACK時はエラーコードをログに残す。
- 複数レスポンスがあるコマンドでは受信ループを設計する。
- 完了レスポンスがあるコマンドでは、完了を受けるまで処理を閉じない。
- ACK/NACKパーサは、起動時スナップショットを入力に取り、設定依存の可変長応答を扱えるようにする。
- 自動読み取り中は、コマンド応答、タグ応答、読取完了応答、アンテナ切替完了応答、キャリア検知応答を同じ受信ループ内で分類する。
- キャリア検知イベント0件、アンテナ切替完了応答OFF時の切替完了ACKなし、TID付加OFF時のTIDなしは、設定どおりなら異常扱いしない。

## 8. AI実装用パーサ契約

生成AIに実装を依頼する場合は、各コマンドカードの `7.4 AI実装用レスポンス定義` を優先して参照してください。実装は、少なくとも次の順番で判定します。

| 順序 | 判定 | 条件 |
|---:|---|---|
| 1 | `INVALID_FRAME` | `STX/ETX/CR/SUM` または `LEN + 7` の総長が不正 |
| 2 | `TIMEOUT` | 期限内に有効フレームを受信しない |
| 3 | `NACK` | `CMD=31h`。DATA内のエラーコードを共通NACK表で読む |
| 4 | `RF_TAG_DATA` | `CMD=6Ch`。Inventory系または自動読み取りのタグ応答 |
| 5 | `ACK` | `CMD=30h`。DATA先頭とPDF該当節で成功応答を読む |
| 6 | `COMPLETION` | 読取完了応答ON時の完了ACK |
| 7 | `ANT_SWITCH_COMPLETE` | アンテナ切替完了応答ON時の切替ACK |
| 8 | `CARRIER_DETECTED` | キャリア検知応答ON時のイベントACK |
| 9 | `NO_RESPONSE` | Restartなど、仕様上ACK/NACKを期待しないコマンド |

`CMD=30h` だけで成功処理を閉じないでください。RFタグ読み取り系ではタグ応答、完了ACK、アンテナ切替完了ACK、キャリア検知ACKが同じ受信ループに混在します。設定がOFFの応答は、返らないことを異常扱いしません。

推奨する実装入力は以下です。

```json
{
  "frame_bytes": "受信フレーム",
  "command_context": "送信したコマンドカードID",
  "settings_snapshot": {
    "rom_version": "取得済みROM",
    "device_model": "機種",
    "connected_antennas": [0, 1, 2],
    "antenna_id_output": true,
    "tid_append": false,
    "read_complete_response": false,
    "antenna_switch_complete_response": false,
    "carrier_detect_response": true
  }
}
```

推奨する実装出力は以下です。

```json
{
  "frame_type": "ACK | NACK | RF_TAG_DATA | COMPLETION | ANT_SWITCH_COMPLETE | CARRIER_DETECTED | NO_RESPONSE | TIMEOUT | INVALID_FRAME",
  "command_card": "対象カード",
  "address_role": "reader_id | antenna_id | unknown",
  "data_length": 0,
  "detail": "応答種別",
  "is_success": false,
  "error": null
}
```

## 9. ログに残す情報

- 実行日時
- 操作者
- 対象機種
- ROMバージョン
- 接続方式
- 起動時スナップショット
- 対象コマンド
- 送信目的
- ACK / NACK / timeout
- NACKエラーコード
- 経過時間
- 停止判断
- 復旧判断

runtime logs、実CSVログ、raw EPC / UII / TID はGitHubにアップロードしないでください。必要な場合はマスク・要約してください。
