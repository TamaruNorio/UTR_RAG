# 仕様照合・試験状態の記録方針

## 1. 状態を分ける

「文書が現在版である」「PDFと照合した」「ソフトウェア試験に合格した」「実機で確認した」は、それぞれ別の状態である。CIの成功、仕様書にコマンドが存在すること、別コマンドの実機成功を、そのカードの実機PASSへ置き換えない。

| 軸 | 記録すること | 根拠不足の場合 |
|---|---|---|
| 文書 | 現在版か、過去の経緯か | 文書の用途を明記する |
| 仕様照合 | PDF番号・版・節・ページ、照合したフィールドと条件、確認日 | 未照合の範囲を列挙する |
| ソフトウェア試験 | 対象コードの版、テスト名、正常・異常条件、実施結果 | 試験結果の所在未確認とする |
| 実機試験 | コマンド、機種、ROM、接続方式、設定、操作、期待結果、観測結果 | 公開証跡から確認範囲を特定できないとする |

## 2. コマンドカードの状態

2026-09-07の保守者方針に従い、仕様上の期待結果は公式PDFを基準とします。54カードの表示は `SPECIFICATION_REFERENCE` とし、PDFに基づく仕様参照資料であることを示します。全フィールドの再照合完了や実機試験の実施を表しません。旧ラベルは[実機確認索引](commands/cards/TEST_STATUS_INDEX.md)に変更履歴として残します。

`verification_status` はカード単位で根拠を判定する。`result_status` はその根拠が裏付ける結果を表す。

| verification_status | 意味 | result_statusの扱い |
|---|---|---|
| `SPECIFICATION_REFERENCE` | 公式仕様を参照するカード。照合の進捗は別途記録する | `NOT_AN_EXECUTION_RESULT`。実機またはソフトウェア試験の結果を表さない |
| `EVIDENCE_SCOPE_UNRESOLVED` | 既存の確認済み表示に対し、カード単位の公開証跡と対象範囲を確定できていない | `NOT_ASSESSED_PER_COMMAND`。失敗・未実施の断定ではない |
| `DOCUMENT_REVIEWED` | 明記した範囲の仕様照合を実施した | 文書照合の結果を記録。実機PASSにはしない |
| `SOFTWARE_TESTED` | 明記した版・範囲のソフトウェア試験を実施した | ソフトウェア試験の結果を記録。実機PASSにはしない |
| `REAL_DEVICE_VERIFIED_WITH_NOTES` | 機種・ROM・接続方式・コマンド・確認範囲・証跡が記録されている | 実際の結果と制限を記録する |

複数の軸の結果を持つ場合、カードの「実機確認」節にそれぞれを併記する。一つのラベルで全機種・全条件を代表させない。文書用の `DOCUMENTATION_CURRENT` は実機試験状態ではない。

「未実施」は、実施していないことが確認できる場合にだけ使う。公開資料に記載がないだけなら「所在未確認」「確認範囲未確定」を使う。仕様参照資料の整備は、別途の実機証跡を必須にせず進める。将来実機PASSを表示する場合には、その実績を裏付ける範囲を記録する。

## 3. 公開可能な証跡の記録様式

| 項目 | 記入内容 |
|---|---|
| 証跡ID・確認日 | 社内記録に対応する公開可能な識別子、確認日 |
| 対象 | コマンドカード、機種、ROM、USB/COMまたはLAN/TCP |
| 使用版 | 仕様書版、文書版、コード版 |
| 前提設定 | モード、応答設定、アンテナ構成など、解釈に必要な条件 |
| 試験項目 | 正常系、異常系、停止、復元など、実施した項目 |
| 期待結果と観測結果 | 両者を分けて記載。未観測・判定不能も明記 |
| 結果と制限 | 合格・不合格・判定不能、未実施の条件、他機種へ一般化できない点 |
| 原典 | PDF節・ページと該当する仕様条件 |

raw EPC/UII/TID、実IPアドレス、顧客情報、認証情報、パスワード、実機生ログは公開しない。公開要約と社内原本の対応だけで追跡できるようにする。

## 4. 更新の単位

状態変更時は、カード本文・frontmatter・[実機確認索引](commands/cards/TEST_STATUS_INDEX.md)・[原典照合一覧](SOURCE_REVIEW_STATUS.md)・対応する評価質問を同じ変更で確認する。状態を変更しただけで、新たな試験を実施したことにはしない。

既存のfrontmatter検証は主にキーと型を検査する。証跡の十分性や仕様内容の正しさは自動判定しないため、本方針によるレビューを別に行う。
