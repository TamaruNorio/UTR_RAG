# RF・キャリア・アンテナ条件

## 1. 目的

この文書は、RF送信、キャリアセンス、LBT、アンテナ設定に関する確認観点を整理します。

公式PDFが一次情報です。実装時は、対象地域、対象機種、ROM、アンテナ構成、現場条件を確認してください。

## 2. 確認すること

- 使用地域
- 使用周波数またはスキャン方式
- 送信出力
- 接続アンテナ本数
- 使用アンテナ番号
- 外部アンテナ自動切替の有無
- LBTエラー時の停止条件
- アンテナエラー時の停止条件

## 3. 実機操作の考え方

周波数変更、送信出力変更、アンテナ設定変更、RF送信信号制御は、プロトコル仕様書に記載された機能です。

条件が揃っていれば実施対象になります。高影響という理由だけで禁止扱いにはしません。

ただし、AIが独断で周波数、送信出力、アンテナ番号、継続判断を決めないようにします。

### 再起動時のRFとポート

[リスタート](commands/cards/4e_9d_restart_reader.md)は保存モードで起動するため、自動読み取りのRFが再開する場合があります（p.17・19–20）。ROM 1.120以前のUTR-S201は起動・リスタート時にも断線確認を行い、キャリアセンス後にキャリアを出力します（p.48–49）。ROM 2.030以降はp.49のキャリア出力を伴う動作時に断線確認を行います。

[FLASH初期化](commands/cards/4e_6f_flash_initialize.md)後にも再起動が必要です。後続処理まで含めてRF条件を確認します。キャリブレーションはポート機能・方向の反映も行うため（p.47）、現在出力と保存設定を区別します。LEDの一時点灯だけを故障とせず、消灯だけで全設定反映やRF停止が完了したとも判断しません。

### 接続診断と状態読取り

[CheckAntenna](commands/cards/55_44_uhf_check_antenna.md)は指定端子に対するRF診断です。キャリアセンス後の反射電力で判定し、未接続だけでなく周囲環境によるマッチング悪化も接続エラーになり得ます。長いケーブルの損失により故障を検知できない場合もあります（p.48・139）。タグ不要とRF不要を混同しません。

[エラー情報読取り](commands/cards/4f_80_read_error_info.md)はRFを使わない情報取得です。2.030以降では正常状態検知によりエラー情報が00hへ戻るため、取得時刻と直前操作を併記します（p.49）。この読取りを読出しクリアと仮定せず、RF診断を観測だけの依頼へ追加しません。

### 9Ehの維持時間と停止

[RF送信信号の制御](commands/cards/4e_9e_rf_carrier_control.md)のON維持は出力開始から最大4秒で、ACK受信起点ではありません。ON再要求で延長できずNACKとなり、OFF→ONは旧Handleを破棄して休止・再センスします。不要になった時点でOFFを要求します（p.129–135）。タグ通信NACKによるHandle破棄をキャリアOFFと同一視しません。

間欠出力対象はS201・SHR201、据置型SUN02の3機種は非対象です（p.56–57）。前回ON時間と設定休止時間を考慮し、50ms+5msを固定の応答期限にしません。9Ehは連続モード中の受付例外ではなく、OFFをモード停止の代わりにしません。timeout時の再ONや、保存モードを考慮しない再起動による停止は自動追加しません。

## 4. エラー時の扱い

LBTエラー、アンテナエラー、timeout、NACKが発生した場合は、ログに残し、作業指示で決めた停止条件に従います。

異常発生後にAI判断だけで再送、継続、別設定への変更を行わないでください。
