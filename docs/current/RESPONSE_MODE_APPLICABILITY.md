# 読み取りモード別の応答・設定の適用範囲

## 原典と用途

[公式PDF Ver.1.17](https://www.product.takaya.co.jp/dcms_media/other/TDR-MNL-PRC-UTR-S201-117.pdf) の §7.1、§7.2、§7.4.25、§7.5.1 を横断して、単発コマンドと自動読み取りの混同を防ぎます。確認日2026-09-06。抽出テキストによる部分照合であり、機種・ROM別の全条件や実機試験の完了を表しません。

## 1. 単発の終了と、連続処理中のサイクル通知

| 対象 | 応答の意味・条件 | 原典 |
|---|---|---|
| コマンドモードのUHF_Inventory | 正常動作ではタグデータの後に読み取り完了応答。タグ0枚は完了応答のみ。自動読み取り用の通知OFFを根拠に、この完了応答を不要としない | §7.5.1 p.263–264 |
| UHF連続インベントリモード | 読み取りサイクル終了時のレスポンスを「返す」と設定した場合、各サイクルの枚数・チャンネルを返す。0枚でも返る | §7.1 p.114、§7.4.25 p.233–234 |
| UHF連続インベントリリードモード | 対応設定が「返す」の場合、読取枚数レスポンスを返す。0枚でも返る | §7.2 p.120、§7.4.25 p.233–234 |

連続モードの枚数応答は、アプリ全体や継続受信の終了を意味しません。ログの `COMPLETION` という名前だけで単発・連続のどちらかを判断せず、動作モード、実フレーム、設定を併せて確認します。分類名の変更やパーサ改修は後工程で扱います。

listen中に枚数応答がない場合、通知OFFなら正常な不在として扱えます。設定不明なら正常・異常を確定せず、ONならサイクルの成立、受信期間、通信状態を調べます。タグデータが続いているだけで通知設定への適合まで確認済みとはしません。

## 2. 通知設定を全モードへ一般化しない

| 項目 | 適用範囲と解釈 | 原典 |
|---|---|---|
| サイクル終了通知 | 自動読み取りモードに適用する。単発Inventoryの完了応答とは条件を分ける | §7.4.25 p.234 |
| アンテナ自動切替終了通知 | 自動読み取りで、通知設定と切替設定の条件が成立したときに返る。使用するアンテナ全体の切替終了を、各アンテナ切替ごとの通知と混同しない | §7.1 p.115、§7.2 p.121、§7.4.25 p.235 |
| キャリア検知通知 | 自動読み取りで、通知設定が有効かつ検知があった場合に返る。コマンドモードではこの通知は返らず、キャリア開始が待ち時間内にできない場合はNACKになる | §7.1 p.116、§7.2 p.122、§7.4.25 p.235 |

### 2.1 切替終了通知の識別とADR

確認日2026-09-08。根拠は§7.1 p.115、§7.2 p.121、§7.4.25 p.235です。

| 動作モード | CMD | LEN | DATA | ADR |
|---|---|---|---|---|
| UHF連続インベントリ | `30h` | `02h` | `[10h, 01h]` | リーダライタID |
| UHF連続インベントリリード | `30h` | `02h` | `[14h, 01h]` | リーダライタID |

通知設定が「返す」で、対象機種の切替設定条件を満たす場合に、使用対象の全アンテナでの読み取り終了時に返ります。タグ読取りの成否に依存しません。通知に枚数フィールドはないため、通知単独でタグ0枚とも断定できません。

アンテナID出力ONでも、この通知のADRはリーダライタIDです。タグデータのADRと同じようにアンテナ番号へ変換しません。設定の読取り・書込みACKはLEN=08h、詳細43h/33h、サブ00hであり、この通知で設定要求を成功終了しません。

### 2.2 切替方式は対象コマンドの定義を使う

§7.4.20 p.212–214の切替方式は00b=制御しない、01b=制御するで、10bと11bは予約です。通知節にある「複数アンテナを一つのアンテナとして扱う」という説明だけで、予約値を有効値に割り当てません。

この書込みコマンドの自動切替は自動読み取りモード用で、コマンドモードでは行われません。8CH機の書込みは非対応のため、§7.4.26などの機種別条件を別に確認します。[設定書込み](commands/cards/55_33_00_write_antenna_switching.md)と[設定読取り](commands/cards/55_43_00_read_antenna_switching.md)は対応範囲も同一とは限りません。

## 3. TID付加の適用先

TID付加は、連続インベントリリードでは自動読み取り用パラメータ、単発UHF_InventoryReadではコマンド内の指定を参照します（§3.9 p.59、§7.2 p.118–119、§7.5.2）。UHF_InventoryやすべてのACKに同じ設定依存の長さ変化があると一般化しないでください。

TID長は[GS1に基づく単位換算と原典の訂正注記](TID_MEMORY_AND_UNITS.md)を確認してください。原典転記とRAG側の訂正を区別します。

## 4. RFタグ通信関連パラメータの適用範囲

確認日2026-09-10。根拠は§3.8 p.58、§3.12 p.71–74、§7.4.24 p.228–232、§7.4.30 p.249–250です。[RFタグ通信関連パラメータ](commands/cards/55_33_04_write_rf_tag_comm_params.md)は両RAMで同値になりますが、個々の機能の適用先は別に判断します。

| 機能 | コマンドモード | 自動読み取りモード |
|---|---|---|
| Target A/B自動切替 | 動作せず、Inventoryの設定Targetを使用 | 有効ならInventoryごとに交互切替。初回・キャリア休止後は設定Targetから再開 |
| 共通RSSIフィルタ | UHF_Inventory／UHF_InventoryReadに適用 | 連続インベントリ／連続インベントリリードに適用 |
| 個別RSSIフィルタ | UHF_InventoryReadのみ。Inventoryは対象外 | 連続インベントリリードのみ。連続インベントリは対象外 |

有効な共通RSSIフィルタは閾値未満のタグ読取りレスポンスを抑制します。閾値以上でも、有効な個別フィルタがあれば続けて判定します。共通で抑制したデータを個別条件で復活させません。フィルタによる不通知と、物理的なタグ不在・RF交信禁止を同一視しません。

### 4.1 個別RSSIの有効条件とTID

[個別RSSI設定](commands/cards/55_39_write_rssi_filter.md)はROM Ver.2.100以降で、FLASHに保存されます。全No.無効なら個別判定を行わず、「条件不一致データ=破棄」だけで全破棄にはなりません。有効な条件をNo.順に調べ、最初にデータ条件が一致したNo.のRSSI判定で終了します。RSSI不足を理由に次の条件へ進みません（p.249–253）。

判定対象がTIDなら、TID非付加設定でも内部でTIDを読みますが、出力には付加しません。指定MemBankが1 Wordなら、後半16 bitが不定のためマスクの後半を0にします（p.250）。設定の読取りACKに含まれる閾値は保存設定で、読取タグの測定RSSIではありません。

閾値の表現と等号に原典内の不一致があり、[OPEN-019／020](SOURCE_REVIEW_STATUS.md)で訂正確認中です。

## 5. 自動読み取り中の受付とモード切替

確認日2026-09-11。§2.2 p.17、§2.4–2.5 p.19–20、§7.4.1 p.152、§7.4.16 p.188–189を照合しました。

連続インベントリ／連続インベントリリード中に受け付ける例外は、動作モード書込み・ブザー制御・LED&ブザー制御・ROM読取り・チップバージョン読取りの5つです。それ以外は基本的に受け付けず、動作保証がありません。[モード読取り](commands/cards/4f_00_read_reader_mode.md)や設定取得、リスタートも例外に含まれません。

[モード書込み](commands/cards/4e_00_10_write_reader_mode.md)で00hのコマンドモードへ戻してから通常コマンドを実行します。65hと66hの切替も00hを経由します。接続時の元モードやブザー値が不明なら、初期値で補って復元済みとしません。観測だけの依頼で、設定取得のための停止を自動実行しません。

### 5.1 切替ACKと観測の範囲

書込みACKはLEN=00h・DATAなしで、指定モードが返るわけではありません。00hへ復帰後の現在値は読取りで確認できますが、65h／66hへ移った後の無条件の読戻しは保証されません。切替ACK・要求値・実際の非同期応答は別々の確認結果です。

モード読取りACKはLEN=09hの固定形式です。切替直後の自動応答や停止前から転送中のデータを、そのACKと混同しません。最後のタグ受信や無応答だけで物理RF停止時刻を確定しません。ACKと自動応答の厳密な前後関係、切替完了までの最長時間は未確認です。
