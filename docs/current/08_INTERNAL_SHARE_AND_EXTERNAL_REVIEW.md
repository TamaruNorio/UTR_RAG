# レビュー指針

この文書は、UTR_RAG をレビューに出すとき、または第三者に確認してもらうときの説明方針を整理します。

社内レビューに限定しません。社内、協力会社、代理店、外部技術者など、確認相手に応じて、共有範囲と前提情報を調整してください。

## 1. レビュー時の説明

UTR_RAG は、UTR-S201 シリーズの通信プロトコル理解、実装支援、レビュー、段階的な実機確認を、AIとのペアプログラミングで進めやすくするためのドキュメントリポジトリです。

公式PDFが一次情報です。このリポジトリは公式PDFの代替ではありません。

PDF原本は、社内の正式な配布場所または管理場所から別途準備してください。GitHubにはPDF原本をアップロードしないでください。

## 2. レビューしてよい内容

- このGitの目的が分かりやすいか
- AIペアプログラミングで使いやすい構成になっているか
- コマンド一覧とコマンドカードをたどりやすいか
- ACK / NACK / timeout / LBT / antenna error の扱いが理解しやすいか
- ROMバージョン、シリーズ名、対象機種の確認手順が分かりやすいか
- 実装前に確認すべきパラメータや現場条件が整理されているか
- 実機確認の手順、ログ、停止条件が分かりやすいか
- Python、C#、C++、JavaScriptなど、任意の実装言語へ展開しやすいか

## 3. 別判断が必要な内容

以下は、レビューコメントを受けること自体は可能です。ただし、実施判断は別途行います。

- 顧客提供
- 一般公開
- 海外運用
- 海外販売
- 量産適用
- 公式PDFの代替としての利用
- 周波数、送信出力、アンテナ構成など、地域条件や現場条件に影響する運用

## 4. 実機操作に関するレビュー観点

プロトコル仕様書に記載され、対象機種、ROMバージョン、地域条件、現場条件を満たすコマンドは、実装・実機送信の対象にできます。

周波数変更、送信出力変更、アンテナ設定変更、InventoryParam / SelectParam / ExpandSelectParam 変更なども、必要に応じて実施対象になります。

レビューでは、AIが独断で次のことをしない構成になっているかを確認してください。

- 作業指示にないコマンドを追加する。
- 周波数、送信出力、アンテナ番号などの値を勝手に決める。
- 対象機種、ROMバージョン、地域条件を確認せずに送信する。
- NACK、timeout、LBT、アンテナエラー発生後に勝手に継続判断する。

## 5. GitHubにアップロードしない情報

以下はGitHubにアップロードしないでください。

- PDF原本
- runtime logs
- 実CSVログ
- 顧客情報
- 実IPアドレス
- raw EPC / UII / TID
- 認証情報
- 完成Hex
- SUM計算済み送信用コマンド例
