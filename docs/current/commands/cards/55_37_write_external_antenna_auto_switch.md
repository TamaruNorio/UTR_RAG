# 外部アンテナ自動切替設定の書き込み

## 1. コマンドの位置づけ

このカードは、UTR-S201 シリーズ通信プロトコル説明書 Ver.1.17 に記載された **外部アンテナ自動切替設定の書き込み** を、AIとの実装・レビュー・検証で参照しやすくするための整理資料です。

- PDF章番号: `7.4.26`
- コマンド分類: リーダライタ設定
- 確認区分: `settings-change`
- 操作レベル: write/configuration
- コマンドバイト: `55h` / 詳細コマンド: `37h` / サブコマンド: `null`
- 確認状態: `SPECIFICATION_REFERENCE`
- 結果状態: `NOT_AN_EXECUTION_RESULT`

本カードは仕様参照資料です。PDFを期待結果の基準とし、実機試験の実施結果とは区別します。[確認状態索引](TEST_STATUS_INDEX.md)を参照してください。

## 2. 目的

このコマンドの目的は、**外部アンテナ自動切替設定の書き込み** です。

詳細なフィールド定義、データ長、レスポンス形式は公式PDFを一次情報として確認してください。このカードは、公式PDFを置き換えるものではなく、AIに実装やレビューを依頼するときの補助資料です。

## 3. 使用可否・位置づけ

判定: `SUPPORTED`（8CH仕様の機種に限定）

PDF §7.4.10 p.175、§7.4.26 p.237に基づき、8CH仕様のリーダライタを対象とします。1CH・4CH系のアンテナ切替設定と混在させません。

ただし、仕様に存在することと、実機へ送信してよいことは別です。実機送信前には、対象機種、ROMバージョン、接続先、パラメータ、影響範囲、復旧方法、停止条件を確認してください。

## 5. 実装前の確認事項

実装前に、少なくとも以下を確認してください。

1. ROMバージョンを読み取り、シリーズ名と対象機種を確認する。
2. 対象コマンドが、その機種・ROMで利用可能か確認する。
3. 読み取り専用か、設定変更か、タグメモリ操作かを分類する。
4. 実機送信が必要な場合は、接続先、タイムアウト、ログ保存先、停止条件を決める。
5. 周波数、送信出力、アンテナ設定、FLASH、タグメモリに影響する場合は、事前承認を取る。

## 6. PDF仕様フィールド定義

### 適用範囲の補足（原典転記と区別）

根拠: §7.4.10 p.175–176、§7.4.26 p.237–240、§3.11 p.67–68。

- DATA[4..11]はアンテナ出力1～8の接続数を表す8個の設定値で、bit maskや単一の外部アンテナ番号ではありません。接続数32は、対応アンテナの外部番号0～31に相当する個数です。接続数の読取りだけで実配線や接続OKを検出したとはみなしません。
- UTR-SUN02V-8CHは対応する外部アンテナと構成に応じて扱います。UTR-SUN02-8CHは各出力1本のみなので、0/1で使用対象を構成します。表の0～32を根拠に、この機種が各出力32本を制御できるとは判断しません。範囲外指定時の具体的な応答コードは推測しません。

### 接続数が参照される条件

| 動作条件 | 使用アンテナの決まり方 |
|---|---|
| コマンドモード | 使用アンテナ番号書込みのコマンド用設定を使う。接続数は巡回対象の選択に使わない |
| 自動読み取り・切替OFF | 使用アンテナ番号書込みの自動用設定を使う。接続数は参照しない |
| 自動読み取り・切替ON | 自動用設定のアンテナを起点に、接続数で定めた対象を巡回する。接続数0の出力には切り替えない |

全8出力の接続数を0に設定しようとするとNACKです（p.239）。停止操作の代わりに全ゼロを書き込まないでください。切替bit0と外部アンテナID出力bit1は別の設定です。ID出力ONは自動切替ONを意味しません。

### 保存先・応答の区別

RAMの片方への書込みは他方へ反映せず、FLASH書込みは両RAMへ反映されます（§3.12 p.72–74）。[保存先と復元](../../RAM_FLASH_IMPACT_MATRIX.md)を確認します。設定の読戻し、物理接続確認、自動切替中の現在位置の読取りは別の確認です。

アンテナID出力はタグデータ応答のADRに関係します（§5.2 p.99）。本設定ACKのADRはリーダライタIDであり、DATA[4..11]もアンテナ番号に変わりません。切替終了通知との分離は[モード別適用範囲](../../RESPONSE_MODE_APPLICABILITY.md)を確認してください。

## 7. コマンド形式の扱い

コマンド形式は、共通フレームとPDF該当節のフィールド定義に従って実装してください。

公式PDF掲載の完成Hex例は仕様説明として記載します。実機へそのまま送信する許可ではありません。`<...>` を含むマスク例・構造例は実行可能なフレームではなく、掲載SUMも置換後の値として使えません。

利用者の条件に合わせた送信用HexやSUM計算済みコマンドは、対象・値・影響範囲・停止・復旧条件を確認してから扱います。安全ガードを省略した実装コードは記載しません。

AIに実装を依頼する場合は、まずフレーム生成、SUM計算、送信、受信、ACK/NACK解析、timeout処理を分けて設計してください。

## 8. レスポンス処理

レスポンス処理では、以下を区別してください。

- ACK
- NACK
- timeout
- 無応答
- 複数レスポンス
- 完了レスポンス
- LBTエラー
- アンテナ関連エラー
- UHF ICエラー

NACKは共通NACK形式とPDF該当節を併せて確認してください。予約バイトは、PDFで意味が定義されていない限り、独自解釈しないでください。

ACK、後続レスポンス、可変長データの解釈は、対象コマンドのPDF定義と機種・ROM・設定に基づきます。[応答マスタ](../../RESPONSE_AND_NACK_MASTER.md)と[モード別適用範囲](../../RESPONSE_MODE_APPLICABILITY.md)を確認し、TID付加や自動読み取り用の通知設定を、すべてのコマンドACKへ一般化しないでください。

### 8.1 ACK/レスポンス例（設定変更成功時）

| 項目 | 内容 |
|---|---|
| ACK構造 | `02 ADR 30 0C 37 <param_type> 00 <flags> <ant1_count> ... <ant8_count> 03 SUM 0D` |
| `CMD` | `30h`（ACK） |
| `LEN` | `0Ch` |
| `DATA[0]` | `37h`（詳細コマンド: 外部アンテナ自動切替設定書込） |
| `DATA[1]` | パラメータ種類: `00h` コマンドモード / `01h` 自動読み取りモード / `02h` FLASH |
| `DATA[2]` | 予約（通常 `00h`） |
| `DATA[3]` | bit0: アンテナ自動切替、bit1: 外部アンテナID出力、bit2-7予約 |
| `DATA[4..11]` | アンテナ出力1〜8の外部アンテナ接続数（各 `0`〜`32`） |
| PDF掲載レスポンス例 | `02 00 30 0C 37 02 00 01 01 00 00 00 00 00 00 00 03 7C 0D` |
| 注意 | 外部アンテナ自動切替は実機の読み取り順と非同期応答に影響します。ACK構造化は仕様整理であり、自動送信用の許可ではありません。 |

種類を指定して影響する保存先を読戻します。FLASH書込みは動作中の両RAMにも反映されるため、再起動後の保持確認とは別に扱います。一時変更の復元は保存先別の開始値と反映順序を確認します。

### 8.2 NACK例（フォーマットエラーの例）

| 項目 | 内容 |
|---|---|
| 代表NACK Hex | `02 00 31 0A 37 44 00 00 00 00 00 00 00 00 03 BB 0D` |
| エラーコード1 | `44h: FORMAT_ERROR` |
| 見る場所 | コマンドは`31h`、データ部1byte目はエラー発生元の詳細コマンド、データ部2byte目以降がエラーコードです。 |

NACK時は、エラーコード1だけでなく、UHF ICエラー時のエラーコード2、UHF_Encode/BlockWrite2固有の追加コードも確認してください。予約領域は意味定義がない限り無視します。

### 8.3 設定依存の注意

- 設定変更またはタグメモリ変更後は、対応する読み取りコマンドで読戻し確認してください。


### 8.4 AI実装用レスポンス定義

この節は、生成AIや実装者がACK/レスポンス処理を固定文言ではなく、byte位置と設定依存で実装するための機械可読寄りの整理です。公式PDFの該当節を一次情報とし、この表は実装時のチェックリストとして使ってください。

#### 共通フレームoffset

| offset | フィールド | 実装上の意味 |
|---:|---|---|
| 0 | `STX` | 常に `02h`。異なる場合は `INVALID_FRAME` |
| 1 | `ADR` | 通常はリーダライタID。RFタグ応答でアンテナID出力ONの場合は読み取りANT番号 |
| 2 | `CMD` | `30h`=ACK、`31h`=NACK、`6Ch`=RFタグデータ、その他はPDF該当節で分類 |
| 3 | `LEN` | `DATA`部のbyte数。総フレーム長は `LEN + 7` |
| 4..`4+LEN-1` | `DATA` | ACK/NACK/タグ応答ごとの可変領域 |
| `4+LEN` | `ETX` | 常に `03h`。異なる場合は `INVALID_FRAME` |
| `5+LEN` | `SUM` | `STX`から`ETX`までのSUM下位1byte |
| `6+LEN` | `CR` | 常に `0Dh` |

#### 受信分類ルール

| 条件 | 分類 | 実装アクション |
|---|---|---|
| フレーム長不一致、`STX/ETX/CR/SUM`不正 | `INVALID_FRAME` | 破棄し、必要なら再同期する |
| 受信期限内に対象要求の応答を確認できない | `TIMEOUT` | timeoutとして処理し、NACKとは分ける |
| `CMD=31h` | `NACK` | 共通NACK表でエラーコードを読む |
| `CMD=30h`、`LEN=0Ch`、`DATA[0]=37h`、`DATA[1]`が要求した種類と一致 | `ACK` | 対象要求への設定応答として扱う |
| `CMD=6Ch` | `RF_TAG_DATA` | 自動読み取り中の非同期応答候補。通常ACKとは分離する |

対象識別子: コマンド `55h` / 詳細 `37h` / サブ `なし`。


#### ACK/データ部offset

`CMD=30h`、`LEN=0Ch`、`DATA[0]=37h`、`DATA[1]`が要求した種類と一致することを確認します。サブコマンドはなく、DATA[2]もサブコマンドではなく予約です。

| DATA offset | フィールド | 解釈 |
|---:|---|---|
| 0 | `detail` | 37h |
| 1 | `parameter_kind` | 要求した00h/01h/02h |
| 2 | `reserved` | 通常00h。独自解釈しない |
| 3 | `flags` | bit0=自動切替、bit1=外部アンテナID出力、bit2–7予約 |
| 4..11 | `external_antenna_counts` | 出力1～8の接続数。各1byte、表の範囲0～32。機種の接続可能数は別に確認 |

本設定ACKは12byte固定で、切替ON/OFFや接続数によって長さを短縮しません。接続数0の出力もフィールドが残ります。返ったflags・各接続数を要求値と照合し、ACK受信と保存先の読戻し・復元を別に記録します。非同期通知やタグ応答は本要求の完了に代用しません。

#### NACK分類

このコマンドのNACKは共通NACKとして扱います。`CMD=31h` の場合は、成功ACKではなく、以下のoffsetでエラーとして分類してください。

| DATA offset | フィールド | 解釈 |
|---:|---|---|
| 0 | `error_source` | 原則として対象コマンドの詳細識別子。対象: `55h 37h` |
| 1 | `error_code_1` | FORMAT_ERROR、SUM_ERROR、LBT_ERROR、ANTENNA_ERROR、UHF_IC_ERRORなどの主エラー |
| 2 | `error_code_2` | `error_code_1=0Ah` のUHF ICエラー時に参照 |
| 3 | `error_code_3` | UHF_Encode / UHF_BlockWrite2 等でPDF定義がある場合のみ参照 |
| 4 | `error_code_4` | PDF定義がある場合のみ参照 |
| 5..9 | reserved | PDFで意味が定義されていない限り独自解釈しない |

判定: `CMD=31h` を受けた時点で `NACK`。`error_code_1` が0でも成功扱いにしないでください。

#### 判定手順（文書上の仕様）

1. フレーム長、区切り、SUMを検査してからDATAを読む。
2. NACKとACKをCMDで区別し、対象要求との対応を確認する。
3. ACKのLEN・詳細・要求した種類を照合し、予約位置を飛ばしてflagsと8個の接続数を読む。
4. 接続数は設定値として扱い、物理接続の検出結果と混同しない。要求値との一致、読戻し、復元は別に記録する。
5. 通知だけで成功終了せず、対象応答が期限内に得られなければ未完了とする。
