# リスタート

## 1. コマンドの位置づけ

このカードは、UTR-S201 シリーズ通信プロトコル説明書 Ver.1.17 に記載された **リスタート** を、AIとの実装・レビュー・検証で参照しやすくするための整理資料です。

- PDF章番号: `7.3.10`
- コマンド分類: リーダライタ制御
- 確認区分: `reader-control`
- 操作レベル: リーダライタ制御
- コマンドバイト: `4Eh` / 詳細コマンド: `9Dh` / サブコマンド: `null`
- 確認状態: `SPECIFICATION_REFERENCE`
- 結果状態: `NOT_AN_EXECUTION_RESULT`

本カードは仕様参照資料です。PDFを期待結果の基準とし、実機試験の実施結果とは区別します。[確認状態索引](TEST_STATUS_INDEX.md)を参照してください。

## 2. 目的

このコマンドの目的は、**リーダライタをリスタート（再起動）すること** です。

PDF 7.3.10では、リーダライタは本コマンドに対するACK/NACKを返しません。正常系でも「レスポンスなし」になるため、通常のACK待ち実装ではなく、送信後に2秒以上待機し、ROMバージョン読み取りなどの低影響コマンドで復帰確認してください。

## 3. 使用可否・位置づけ

判定: `SUPPORTED`

このコマンドはPDF Ver.1.17のコマンド一覧に含まれるため、仕様上の対象コマンドとして扱います。

ただし、仕様に存在することと、実機へ送信してよいことは別です。実機送信前には、対象機種、ROMバージョン、接続先、パラメータ、影響範囲、復旧方法、停止条件を確認してください。

## 4. 安全性・影響分類

| 項目 | 判定 |
|---|---|
| RF送信 | 再起動時の条件付き影響あり |
| 書き込み操作 | なし |
| FLASH操作 | なし |
| タグメモリ操作 | なし |
| ROM確認 | あり |
| アンテナ条件確認 | 再起動時の条件を確認 |
| タグ条件確認 | なし |
| Accessパスワード確認 | なし |
| パラメータ確認 | なし |
| 明示許可 | 必要 |

高影響コマンドを、高影響という理由だけで仕様上禁止扱いにはしません。ただし、上記の確認事項が揃うまで実機送信しません。

## 5. 実装前の確認事項

実装前に、少なくとも以下を確認してください。

1. ROMバージョンを読み取り、シリーズ名と対象機種を確認する。
2. 対象コマンドが、その機種・ROMで利用可能か確認する。
3. このコマンドはACK/NACKを返さないため、無応答を即エラー扱いしない受信設計にする。
4. リスタート実行後の応答不能時間は約2秒で、次コマンドまで2秒以上空ける。待機だけで完了を断定しない。
5. RAM上のコマンドモード用パラメータ、自動読み取りモード用パラメータがFLASH値で上書きされることを確認する。
6. 実行前に、必要なRAM設定スナップショットと復帰後の再設定要否を決める。
7. 復帰確認には、ROMバージョン読み取りなど低影響の読み取りコマンドを使う。

## 7. コマンド形式・PDFフィールド定義の読み方

この節は、PDF 7.3.10 のコマンド表・注意事項を、生成AIが実装に使える粒度へ分解したものです。このコマンドは、通常のACK/NACK待ちを行うコマンドではありません。

### 7.1 送信コマンドフレーム

| offset | フィールド | byte数 | 値 | 意味 |
|---:|---|---:|---|---|
| 0 | `STX` | 1 | `02h` | フレーム開始 |
| 1 | `ADR` | 1 | 通常 `00h` | リーダライタアドレス。共通通信フォーマットに従う |
| 2 | `CMD` | 1 | `4Eh` | リーダライタ制御コマンド |
| 3 | `LEN` | 1 | `01h` | DATA部は1byte |
| 4 | `DATA[0]` | 1 | `9Dh` | 詳細コマンド: リスタート |
| 5 | `ETX` | 1 | `03h` | フレーム終端 |
| 6 | `SUM` | 1 | `F1h` | PDF掲載例のSUM。`02+00+4E+01+9D+03 = F1h` |
| 7 | `CR` | 1 | `0Dh` | 改行終端 |

### 7.2 コマンド／レスポンス例

| 種別 | Hex / 内容 | 説明 |
|---|---|---|
| 送信例 | `02 00 4E 01 9D 03 F1 0D` | リーダライタへリスタートを要求 |
| レスポンス | なし | PDF上、ACKもNACKも返らない |

このコマンドでは、レスポンスなしが仕様上の正常系です。受信タイムアウトをそのまま通信失敗と決めつけず、「再起動中の無応答」と「送信失敗・未復帰」を分けて扱ってください。

### 7.3 待機と通信確認の意味

p.148はリスタート実行後の約2秒間を応答不能とし、次コマンドまで2秒以上空けるよう指定しています。これは最短待機条件で、2秒経過だけで再起動完了・全設定復元・RF停止を証明するものではありません。ホストでは送信完了時刻を記録して待機し、実機の受信・実行時刻との差と接続方式の遅延を考慮します。

待機後の[ROM読取り](rom_version_read.md)は通信可能かを確かめる手段です。再起動要求が届かず以前の動作が続いている場合もROM読取りに応答できるため、その成功だけを「リスタート実行済み」の証拠にしません。再起動要求の送信結果、通信確認結果、設定反映確認を別に記録します。未復帰時にリスタートやFLASH初期化を自動反復しません。

### 7.4 保存モード・RAM・RFへの影響

リスタートはFLASHを出荷時へ初期化せず、保存されたFLASH値でコマンド用・自動読取り用の両RAMを上書きします（p.148、71–72）。起動モードもFLASH保存値で、常に00hへ戻るとは限りません（p.17）。RAMだけを00hへ変更してから再起動しても、保存モードが65h／66hなら自動読み取りが再開し得ます。

本体キャリブレーションではFLASHからRAMへの反映や汎用ポートの機能・方向の切替を行います（p.47）。現在出力と保存初期値を区別し、外部への信号の影響を確認します。キャリア状態・保持Handle・認証等を再起動前から有効と扱わず、再利用に必要な条件は該当カードで再確認します。内部の全状態の初期値・消去順は未確認です。

ROM 1.120以前のUTR-S201は起動・リスタート時にアンテナ断線確認を行い、これはキャリアセンス後のキャリア出力を使います（p.17、48–49）。ROM 2.030以降の断線確認はp.49のキャリア出力を伴う動作時です。保存モードによる自動RFも含め、rf_emission・requires_antennaを条件付き影響としてtrueにしています。全機種の再起動で常時RFを送信するという意味ではありません。

## 8. 無応答・復帰確認の切り分け

### 8.1 応答分類

要求はCMD=4Eh、LEN=01h、DATA[0]=9Dhの総8 byteです。p.148はACKもNACKも返さないと明記します。無応答は仕様上の想定ですが、到達・実行成功の証明ではありません。通常のACK期限切れとして失敗扱いしたり、無応答だけで成功扱いしたりしません。

直後にACK/NACKらしきフレームを受けても、9Dhの成功ACKや固有NACKを追加しません。未完了の他要求、受信残留、後続の確認要求、フレーム不正を切り分け、対応不明なら未分類にします。自動読み取りの通知は再起動完了応答ではありません。後続ROM読取りのtimeoutやNACKは、その要求の結果として記録します。

### 8.2 受付モードと設定取得

65h／66hの連続モード中はリスタートもFLASH初期化も受付例外に含まれず、動作保証外です（p.19–20）。[モード書込み](4e_00_10_write_reader_mode.md)で00hへ戻してから実行します。停止操作は観測ではなく動作変更です。元値を取得できない場合に初期値で補いません。

再起動後に保存モードで連続動作している場合、ROM読取りは受付例外でも、各種設定読取りは保証外です。通信確認後のスナップショットを無条件で一括取得せず、モード条件を確認します。FLASHと異なっていた両RAMを復元する場合、FLASH読取り結果だけで元RAMを再現できるとは判断しません。

### 8.3 接続方式と未確認範囲

USB/COMとLAN/TCPでは、接続維持・切断検出・再接続を分けて検証します。p.148はCOM再列挙、TCP切断、IP設定初期化を保証していません。再オープンは接続状態に応じたホスト側の復旧判断です。物理電源再投入と本コマンドを、周辺機器や通信モジュールを含めて同一動作とはしません。

再起動実行を直接証明する識別子、全機種の最長復帰時間、受信バッファの扱い、全内部状態のリセット範囲は未確認です。実機確認では機種・ROM・接続先・モード・保存値・開始前RAM・送信時刻・待機・通信確認・反映確認・復元結果を分離して記録します。
