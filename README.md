# UTR_RAG

UTR_RAG は、タカヤ製 UTR-S201 シリーズの通信プロトコル理解、実装支援、レビュー、段階的な実機確認を、AIとのペアプログラミングで進めやすくするためのドキュメントリポジトリです。

対象読者は、AIを使ったペアプログラミング経験があり、Git / GitHub の基本操作を理解している開発者です。実装言語は限定しません。Python、C#、C++、JavaScript、その他の言語でも利用できます。

## 1. 現在版

現在版は **V100 Final documentation package** です。

V100 は、過去の作業履歴を前面に出すのではなく、UTR-S201 シリーズ制御プログラムを作る人が、AIと安全に実装・レビュー・検証を進められるように再整理した最終版ドキュメントです。

## 2. このリポジトリの目的

このリポジトリの目的は、以下です。

- UTR-S201 シリーズのコマンド仕様を探しやすくする。
- AIに渡す前提情報を整理する。
- ACK / NACK / timeout / LBT / antenna error などの応答処理方針を確認しやすくする。
- ROMバージョンとシリーズ名から対象機種を整理しやすくする。
- 実機送信が必要な作業と、机上確認で済む作業を分ける。
- Python、C#など任意の言語へ移植しやすい形にする。
- 高影響コマンドを安全に扱うための条件、確認事項、停止条件を明確にする。

## 3. 公式PDFとの関係

公式PDFが一次情報です。このリポジトリは公式PDFの代替ではありません。

このリポジトリには、PDF原本を置きません。PDF原本は、社内の正式な配布場所または管理場所から別途準備してください。GitHubにはPDF原本をアップロードしないでください。

このリポジトリは、公式PDFを参照しながら、AIと人間が安全に実装・確認を進めるための補助資料です。仕様判断、顧客提供、社外公開、海外利用、量産適用は、別途正式な確認が必要です。

## 5. AIペアプログラミングでの使い方

AIへ依頼するときは、次の順に進めます。

1. 対象機種、接続方式、対象コマンド、実現したい動作を明示する。
2. 必要に応じて、リポジトリ全体、主要ドキュメント、または対象コマンドカードをAIに読ませる。対象が広い場合は全体を読ませ、対象が決まっている場合は該当カードと関連文書を中心に読む。
3. 実装対象を「読み取りのみ」「設定変更あり」「タグメモリ操作あり」「その他の制御操作」に分ける。
4. 実装言語、実行環境、タイムアウト、ログ方針を指定する。
5. まず机上確認または dry-run から始める。
6. 実機送信が必要な場合は、対象コマンド、設定値、対象機、復旧方法、停止条件を作業指示として明確にする。

実装言語は限定しません。C#、Python、C++、JavaScriptなど、対象システムに合わせて選択してください。

## 6. 実機操作の考え方

プロトコル仕様書に記載され、対象機種、ROMバージョン、地域条件、現場条件を満たすコマンドは、実装・実機送信の対象にできます。

周波数変更、送信出力変更、アンテナ設定変更、InventoryParam / SelectParam / ExpandSelectParam 変更なども、プロトコル仕様書に基づき、必要な作業として実施する場合があります。

ただし、AIが独断で実行対象を追加したり、設定値を決めたり、異常時に継続判断したりしないようにします。実機送信する場合は、作業指示として次の情報を明確にします。

- 対象コマンド
- 対象機種とROMバージョン
- 接続方式
- 設定値またはパラメータ
- 実行目的
- 影響範囲
- 復旧方法
- 停止条件
- ログ方針

高影響コマンドを、高影響という理由だけで仕様上禁止扱いにはしません。実施するかどうかは、プロトコル仕様書、対象機器、現場条件、作業目的に基づいて判断します。

## 7. Git運用

- mainを直接変更しない。
- featureブランチで作業する。
- 変更前後に `git status --short` を確認する。
- 差分は `git diff` と `git diff --check` で確認する。
- Pull Requestでレビューしてからmainへ反映する。

## 8. Gitにアップロードしない情報

以下はGitHubにアップロードしないでください。

| 種類 | 扱い |
|---|---|
| PDF原本 | 社内の正式な管理場所から別途準備する。GitHubにはアップロードしない。 |
| runtime logs | ローカル確認用に留め、GitHubにはアップロードしない。 |
| 実CSVログ | 必要に応じてマスク・要約し、原本はアップロードしない。 |
| 顧客情報 | 顧客名、現場名、個別条件を不用意に公開しない。 |
| 実IPアドレス | `192.168.xxx.xxx` のようにマスクする。 |
| raw EPC / UII / TID | 必ずマスクする。 |
| 認証情報 | APIキー、パスワード、トークンを記載しない。 |
| 完成Hex | そのまま実機送信できる形で安易に記載しない。 |
| SUM計算済み送信用コマンド例 | 実機誤送信を避けるため、安易に記載しない。 |

## 9. 完成条件

V100は、AIペアプログラミング用の最終版ドキュメントとして、以下を満たすことを目標にします。

- プロトコル仕様書に基づき、実機送信してよい処理を判断できる。

- PDF原本、ログ、顧客情報などをGitHubにアップロードしない運用が分かる。
